Feature engineering

Three ways to turn CLIF data into model inputs: direct, fe-meds, fe-wide.

All three honor the per-row prediction_dttm cutoff (no data after the prediction point). Pick by how much control vs. convenience you want.

modehowoutputwhen to use
directyour own code over cohort.parquet + _clif loaders / clifpywhatever you buildfull control; custom or novel features
fe-medsflair fe-medsELF-long medication events — raw dose + raw unit, no conversionlightweight; only selected meds
fe-wideflair fe-wideELF-long events for all configured vitals/labs/meds/assessments/respconfig-driven, leak-guarded, everything at once

fe-wide / fe-meds commands

flair fe-wide \
  --feature-config feature_config.yaml \
  --task cohort.parquet \
  --out features.parquet

flair fe-meds \
  --feature-config feature_config.yaml \
  --task cohort.parquet \
  --out meds.parquet

Both read cohort.parquet (for hospitalization_ids and per-stay prediction_dttm), load CLIF via clifpy, truncate at the prediction point, and write ELF-long parquet.

The ELF long schema

Both extractors emit the same Event List Format — one row per clinical event — so downstream code works with either:

columntypenotes
subject_idstr= patient_id
timedatetime (tz-naive)always ≤ prediction_dttm
codestr<DOMAIN>//<category>//<unit>
numeric_valuefloatnullable (numeric events)
unitstrrequired where numeric_value is set
text_valuestrnullable (categorical events)
hospitalization_idstrrequired
hospitalization_join_idstrrequired (stitched-hospitalization key)

feature_config.yaml

flair init-config scaffolds it. It drives both extractors:

clif_config: clif_config.json
output_directory: ./output/features

# fe-wide: time-series -> clifpy create_wide_dataset -> melted to ELF long
wide:
  vitals:
    categories: [heart_rate, sbp, dbp, map, spo2, respiratory_rate, temp_c]
  labs:
    categories: [creatinine, lactate, wbc, hemoglobin, platelet_count, sodium, potassium]
  medication_admin_continuous:
    categories: [norepinephrine, epinephrine, vasopressin, propofol]
  patient_assessments:
    categories: [gcs_total, RASS]
  respiratory_support:
    columns: [device_category, mode_category, fio2_set, peep_set]

# fe-meds: lightweight med stream, raw dose + raw unit, NO conversion
meds_stream:
  medication_admin_continuous:
    categories: [norepinephrine, propofol]
  medication_admin_intermittent:
    categories: [vancomycin, cefepime, piperacillin_tazobactam]

Categories are CLIF 2.1 mCIDE values; unknown ones warn but don't fail.

Units

Units are deterministic per mCIDE category and are not converted at extraction: labs read their reference unit from clifpy's schema, vitals/respiratory use fixed mCIDE units. The fe-meds path keeps the raw per-row med_dose_unit (charted as "UNK" when a dose has no unit) so you can convert later. Use the optional units: block to override any default.

From ELF to model features (count truncation)

The reference baseline counts ELF codes into a sparse matrix. Before counting, codes are truncated to fixed levels so units and order-types don't leak in as separate features:

  • numeric codes → 2 levels: LAB//lactate//mmol/l//bmp → LAB//lactate
  • categorical codes → 3 levels: RESP//device_category//imv (unchanged)

Then events with time < prediction_dttm are counted per prediction_id, and the vocabulary is fit on the train split only.
