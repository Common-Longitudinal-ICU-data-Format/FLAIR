Building reports

Turning a predictions parquet into the aggregate-only JSON bundle a site uploads.

The key choice is --mode — how a task's predictions are scored.

The command

flair build-report preds.parquet \
  --task task1_icu_daily_mortality \
  --out ./report/ \
  --mode landmark \
  --cohort cohort.parquet \
  --split test \
  --viz            # or --no-viz
flagdefaultpurpose
--task(required)task name
--out(required)output directory for the JSON bundle
--modeinferredepisodic | peak | landmark
--splittestwhich split to analyze
--cohort—joins demographics + window_number when absent from preds
--viz/--no-vizonrender local sanity-check PNGs (never uploaded)

The predictions parquet

Required columns: hospitalization_id, split, <label_column>.

  • binary → y_pred and/or y_prob (recommended — enables calibration, DCA, fairness AUROC)
  • multiclass → y_pred + class_probs_<class>
  • regression → y_pred_value

Carry hospitalization_join_id, window_number, and demographics through too (or pass --cohort and they're joined in). y_prob must be a valid probability in [0, 1] with no nulls.

Choosing --mode

modeuse forpillars produced
episodicone-per-stay tasks (T3, T5)discrimination, calibration, dca, fairness
landmarkcontinuous tasks, per-lead-time honesty (T1, T2)the four pillars per landmark (12 risk-set lead times) + leadtime
peakcontinuous screening (T4)discrimination + fairness only
The rule that bites: if you omit --mode it is inferred from META's temporal_pattern (episode → episodic). But a continuous task with no --mode is an error — you must explicitly pick peak or landmark.
  • landmark freezes the clock L windows before each stay's endpoint, scores one row per stay at that lead time, and repeats for L = 0..11 → an honest skill-and-calibration curve over time. It also emits leadtime: per-window detection sensitivity, median lead-time before the first alert, and mean risk trajectory by eventual outcome.
  • peak collapses each stay to its worst (peak) risk — deployment-like for screening discrimination, but calibration/DCA are omitted because peak-selection breaks calibration (the "peak-calibration trap").

What each pillar reports

pillarcontents
discriminationAUROC, AUPRC, ROC/PR curves, operating point at the clinical threshold (sensitivity/specificity/PPV/NPV/F1), NNE
calibrationECE, Brier, slope, intercept, reliability + smoothed curves
dcadecision-curve net benefit across a threshold grid
fairnessper-subgroup (sex, race, ethnicity, age-bin) AUROC + parity gaps

Every metric carries a 500-replicate bootstrap 95% CI. Cell suppression (<10) and subgroup dropping (n < 10) are applied so nothing identifying leaves the site. Output is one JSON per pillar under --out (landmark adds leadtime.json); --viz writes matching PNGs under report/viz/ for local validation only.
