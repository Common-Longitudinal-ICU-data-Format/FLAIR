Loading a task → cohort

flair load-task task1_icu_daily_mortality \
  --clif-config clif_config.json \
  --out cohort.parquet \
  [--train-end YYYY-MM-DD] [--test-start YYYY-MM-DD]

This runs the task's build() and writes cohort.parquet plus cohort.table1.json (cohort characteristics, auto-generated).

The cohort contract

columnrole
hospitalization_idraw hospitalization key
hospitalization_join_idstitched-hospitalization (stay) key
prediction_dttmthe no-data-after cutoff for that row
<label_column>the task label (e.g. label_mortality)
splittrain / test
demographicsage_at_admission, sex_category, race_category, ethnicity_category
window_number1-based k-th prediction per stay (always 1 for one-per-stay)
prediction_idauditable per-row key

prediction_id = {hospitalization_join_id}-{hospitalization_id}-{patient_id}-{window_number} — all four segments always present, so any prediction row traces back to its stitched stay, the specific hospitalization, the patient, and the window.

Leakage rule. A row may use all data with time ≤ prediction_dttm and nothing after it.

Authoring a new task (the "task maker")

A task is a single Python file dropped into flair_benchmark/tasks/<name>.py that exposes a META dict and a build() function. The catalog auto-discovers it — no registry edits.

META — required fields

The taxonomy triple (validated; reviewers read this before any code):

fieldallowed values
task_classoutcome, deterioration, intervention, operational
temporal_patternepisode, fixed_horizon, continuous
prediction_unitone-per-stay, one-per-window

For binary tasks, also required: clinical_threshold (a float in (0, 1)) and clinical_direction ("above" or "below"). Plus descriptive fields: name, display_name, task_type, label_column, positive_class, clinical_action, windows, cohort docs, evaluation_metrics.

build() — signature & contract

def build(clif_config: str, train_end: str | None,
          test_start: str | None) -> pl.DataFrame:
    ...
    return finalize_cohort(df, OUTPUT_COLS, META)

It must end with finalize_cohort(df, OUTPUT_COLS, META), which selects your OUTPUT_COLS and stamps on window_number + prediction_id.

Author decision checklist

  1. Cohort scope — all-comers ICU? hospital-wide? specific inclusion/exclusion?
  2. Label anchor — what clinical event defines the positive label?
  3. Prediction timing — one-per-stay (episode) or one-per-window (continuous)?
  4. Threshold + direction — at what risk do you act, and above or below?
  5. prediction_dttm — the strict no-data-after cutoff for each row.

Acceptance

A new task enters the federated suite after: reproducibility against MIMIC-CLIF, a clinician-led face-validity review, and site-governance acceptance at a minimum of two consortium sites.
