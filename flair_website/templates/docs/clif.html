CLIF data layer

The common schema FLAIR is anchored on, and how the library loads it.

FLAIR is anchored on the Common Longitudinal ICU Format (CLIF) — a critical-care minimum dataset that harmonizes ICU EHR content into a small set of relational tables with standardized vocabularies (mCIDE) for vital-sign, lab, medication, and respiratory categories. Because CLIF standardizes the data elements themselves, a model meets the same coded vocabulary at every site, so FLAIR measures genuine cross-site generalizability.

Two equivalent ways to consume CLIF

  1. Native clifpy tables — the canonical CLIF Python interface, one class per table.
  2. MEDS event stream — via the maintained CLIF→MEDS bridge.

FLAIR supports both; nothing locks you into one representation.

How FLAIR loads CLIF

The loaders in flair_benchmark/_clif.py wrap clifpy and standardize the load:

clifpy table.from_file(data_directory, filetype, timezone, filters)
        → pandas → polars (pd_to_pl) → strip timezone to local wall-clock

Public loaders (each filters by hospitalization_id and, where relevant, category): load_hospitalization, load_patient, load_vitals, load_labs, load_medication_admin_continuous / _intermittent, load_respiratory_support.

Timezone note. clifpy returns tz-aware datetimes typed to cfg["timezone"]; FLAIR's pd_to_pl strips the tz so all datetimes are naive wall-clock already local to the site. A literal anchor like "07:00" in a task therefore means local hospital time.

Stitched hospitalizations

Adjacent hospitalizations less than stitch_time_interval_hours apart (default 6) are merged into a single stitched hospitalization, keyed by hospitalization_join_id. This is the stay-level grain: one entity even when it spans several raw hospitalizations, and a stitched hospitalization is never split across train and test.

Going deeper: clifpy directly

For custom work — pulling raw tables, or computing severity/comorbidity scores — use clifpy directly. FLAIR already uses clifpy's compute_sofa_polars (SOFA), calculate_cci (Charlson), and calculate_elix (Elixhauser) when building each task's Table 1.
