# FLAIR 101

A practical, top-to-bottom guide for an **external user** — a method developer, a site
data steward, or someone authoring a new benchmark task. Read this page for the big
picture, install, and an end-to-end quickstart; follow the links for the detail.

> FLAIR is a **federated** ICU benchmark: the code travels to the data, and only
> aggregate JSON ever leaves a site. You develop and self-evaluate against the public
> **MIMIC-CLIF** dataset; the exact same code later runs unmodified behind a hospital's
> firewall.

---

## 1. What FLAIR is

**The model-to-data loop.** A model is built and validated against public MIMIC-CLIF,
reviewed, then shipped to each consortium site. Each site runs it against its own CLIF
tables and returns a small bundle of aggregate-only JSON. Patient-level rows never move.

**The package:**

| package | CLI | what it gives you |
|---|---|---|
| `flair-benchmark` | `flair` | the library: task catalog, cohort builder, feature extractors, report builder |

You bring the model. FLAIR builds the cohort and scores your predictions; what
happens in between is yours.

**Privacy guarantees baked into the library:**
- No patient rows leave a site — outputs are JSON aggregates only.
- Cell-count suppression: any count `< 10` is written as `"<10"` in `table1.json`.
- Demographic subgroups with `n < 10` are dropped entirely from the fairness block.

**The development pattern.** MIMIC-CLIF (≈70k ICU stays, CLIF v2.1 schema) is the public
entry point. Because every consortium site shares the same schema and standardized
vocabulary (mCIDE), the code you write and test on MIMIC runs unchanged at each site.

## 2. Install & first config

```bash
pip install flair-benchmark          # core library + `flair` CLI
pip install "flair-benchmark[viz]"   # add matplotlib for local sanity-check PNGs
```

Scaffold the two config files from the CLI:

```bash
flair init-config --out .
# writes clif_config.json + feature_config.yaml (pass --force to overwrite)
```

**`clif_config.json`** tells FLAIR where your CLIF data lives and how to read it:

| field | required | meaning |
|---|---|---|
| `site` | yes | site identifier. `"mimic"` (case-insensitive) triggers the deterministic **random** 75/25 split (its dates are shifted); any other name gets the **temporal** 75/25 split. The `DATA_CUTOFF` filter (rows with `prediction_dttm` after **2025-12-31**, fixed in `constants.py`) applies at every non-mimic site, in *all* split regimes — including explicit `--train-end` / `--test-start`. Both deal at stitched-encounter grain — see [tasks.md](101/tasks.md#the-traintest-split). |
| `data_directory` | yes | root folder of your CLIF parquet/CSV files |
| `filetype` | yes | `"parquet"` or `"csv"` |
| `timezone` | yes | site-local tz, e.g. `"US/Eastern"` — clifpy returns tz-aware times; FLAIR strips to local wall-clock. No default: a missing value raises `ValueError` |
| `stitch_time_interval_hours` | no | gap (default `6`) below which adjacent hospitalizations merge into one **stitched encounter** (`hospitalization_join_id`) |
| `cache_directory` | no | where intermediate artifacts (encounter index, cohort scores) are cached. Default `./output/_flair_cache`, relative to the directory you run `flair` from. FLAIR never writes into `data_directory` |

Default scaffold:

```json
{
    "site": "sitename",
    "data_directory": "/path/to/clif/data",
    "filetype": "parquet",
    "timezone": "US/Central",
    "stitch_time_interval_hours": 6,
    "cache_directory": "./output/_flair_cache"
}
```

Edit `site`, `data_directory` and `timezone`, then you're ready to load a task. Leaving
`site` as `"sitename"` gets you the temporal split and the date cutoff; for MIMIC-CLIF
it must be `"mimic"`, or the cutoff empties its shifted-date cohort.

## 3. End-to-end quickstart

```bash
# 0. install + scaffold
pip install "flair-benchmark[viz]"
flair init-config --out .
#   …edit clif_config.json: set site, data_directory + timezone…

# 1. see what tasks exist
flair list-tasks

# 2. build a cohort for one task  ->  cohort.parquet + cohort.table1.json
flair load-task icu_daily_mortality \
  --clif-config clif_config.json \
  --out cohort.parquet

# 3. engineer features  ->  ELF-long med event parquet (config-driven; cut per
#    encounter at its latest feature_cutoff_dttm — filter each row to its own
#    feature_cutoff_dttm before training)
#    (for vitals/labs/resp, call clifpy's create_wide_dataset yourself and apply
#     the feature_cutoff_dttm filter — see 101/features.md)
flair fe-meds \
  --feature-config feature_config.yaml \
  --task cohort.parquet \
  --out meds.parquet

# 4. …train YOUR model on meds.parquet + cohort.parquet…
#     produce preds.parquet with: hospitalization_join_id, prediction_id, split,
#     label col, y_prob

# 5. build the report bundle  (mode inferred: continuous task -> continuous)
flair build-report preds.parquet \
  --task icu_daily_mortality \
  --cohort cohort.parquet \
  --out ./report/
```

The result is a set of aggregate JSON files (plus optional PNGs) under `./report/` — the
only thing a site ever uploads.
