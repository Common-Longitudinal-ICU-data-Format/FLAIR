05 · Compliance · Infra

Immutable. Offline. Aggregate-only.

Three layers keep PHI inside hospital walls: containers that can't reach the internet, a compliance test every submission must pass, and a report CLI that suppresses every small cell before bytes leave the site.

Container model

Offline
--network=none at runtime
No egress. Kernel-level isolation. No retry logic that could exfiltrate on next call.
Immutable
Read-only image · hash-pinned
Built once, signed, hash recorded. Any in-place modification breaks verification.
Reproducible
Lockfile + Containerfile
uv/pip-tools manifest pinning every transitive. Two sites build identical bytes.
Read-only data mount
Site's CLIF parquet → mounted RO
Container can't mutate the source. No write path off the cohort parquet.

The FLAIR compliance test

Every submission runs this gauntlet at the portal before any site sees it. Pass everything or no rollout.

CheckWhat it proves
Unit tests greenSubmitter's own logic works on toy data.
End-to-end run on MIMIC-CLIFContainer + featurizer + model load + predict all chain.
Output JSONs validate against schemabuild-report contract honored — leaderboard can ingest.
Egress trace cleanNo connect() / no DNS / no outbound socket in the trace.
Hash-deterministic loadModel loads to identical bytes across two runs.
Build hash matchesContainer rebuilt from same Containerfile + lockfile → identical SHA.
Output bytes deterministicSame input cohort + same model → identical output JSON.
Suppression honoredNo cell < 10 leaks; no fairness subgroup < 10 surfaces.

If any check fails, the portal returns the trace to the submitter. The container does not get listed.

Storage + transport

Rush Azure Blob. HIPAA-eligible storage with a REST API. Sites POST their per-task JSON bundles directly into the study's blob container; the FLAIR aggregator reads them out. No staging server in between, no on-disk PHI even momentarily.

PHI guarantees enforced by the CLI

The library itself enforces these — not site policy, not site PI vigilance:

  • HIPAA cell suppression in table1.json — counts < 10 → "<10".
  • Subgroup drop in fairness.json — any group with n < 10 is omitted entirely.
  • Calibration-bin suppression in curves.json — bins with count < 10 report null for true rate.
  • Per-task script SHA-256 stamped into every JSON — aggregator verifies byte-identical code across sites.

What we are not trying to do

FLAIR-Bench is not a sandbox. It does not enforce network isolation at runtime — that's the CLIF-WorkBench container's job. It does not run an IRB review — that's each site's job. It does not host the final paper — that's NEJM AI. It does enforce: standardized output shape, deterministic hashing, and cell suppression. That's enough to make federated evaluation tractable.
