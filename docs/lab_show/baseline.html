03 · Baseline · NEJM AI anchor

Beat the count-vector.

Every leaderboard needs a floor. FLAIR's floor is a gradient-boosted machine over mCIDE count vectors: cheap, portable, explainable. Every future model is scored against it across all 17+ sites — from traditional ML (logistic regression, random forest, XGBoost) to deep sequence models to foundation models. One leaderboard, one comparator, every model class on the same axis.

The featurization

For each patient's input window, count how many times every mCIDE category appears. That's the whole vector — one scalar per category, across every CLIF long-table.

Why count-vector?

Cheap
Sparse vector → XGBoost in minutes on a laptop.
Portable
No tokenizer, no embedding, no GPU. Containerizes trivially.
Explainable
SHAP per feature → "creatinine count drove this prediction."
Reproducible
Identical featurizer + identical model object → byte-identical scores at every site.

The model

XGBoost — gradient-boosted tree ensemble. Binary classifier for T1, T2, T6, T7, T8, T9, T10; multiclass for T3; regression for T4, T5. One booster per task. Hyperparameters frozen at submission time; no per-site tuning.

The scoreboard prompt

"Beat the count-vector XGBoost baseline."

That is the organizing question for every submission. Bring your transformer, your foundation model, your hand-crafted feature set — and beat a count-vector. If it doesn't beat the baseline on the federated leaderboard, the leaderboard tells the story.

Training corpus

Baseline is trained on MIMIC-CLIF (~70k ICU stays, single site) and shipped as a fixed model object. Every consortium site evaluates that same object on its private data — no fine-tuning, no re-training. This is what makes the comparison clean: when a new submission beats the baseline at site X, it's not because the baseline never saw site X.
