Task T5 · episode · one-per-stay

Unplanned ICU Readmission

At the end of a patient's first ICU stay, predict whether the patient will return to the ICU later in the same hospitalization through an unplanned path. The signal is derived entirely from the CLIF ADT location history. A planned return — ICU → Procedural → ICU (a trip to the OR or cath lab and back) — is not counted: the procedural segment is removed and the two ICU stays merge into one. One prediction per surviving hospitalization.

Code note Implemented in task5_icu_readmission.py on the stitched-encounter grain: compute_readmission_timing runs across the whole stitched encounter's ADT stream, so a true re-admission that the stitcher merged is read as one continuous location history. Constant verified against code: MIN_ICU_STAY_HOURS = 1.

FLAIR operational definition

Anchors and windows

Let \(H_i\) denote a hospitalization. From the CLIF ADT table, compute_readmission_timing computes a merged location sequence and, from it, the first ICU-stay window \([t^{\text{ICU}_1,\text{start}}_i,\, t^{\text{ICU}_1,\text{end}}_i]\) and the start time of a second ICU stay (if any).

Location standardization
Each adt.location_category is lowercased and mapped to a coarse bucket std_location ∈ {ICU, Ward, ER, Procedural, Other} via LOCATION_MAPPING. Stepdown, L&D, hospice, psych, rehab, radiology, dialysis, and other all map to Other.
Procedural-sandwich removal (planned readmission)
A row with std_location = Procedural whose immediate predecessor and successor (within \(H_i\), ordered by in_dttm) are both ICU is deleted. This collapses ICU → Procedural → ICU into a single ICU stay: a planned procedural excursion is not a readmission.
Consecutive-location merge
After sandwich removal, consecutive rows with the same std_location are merged into one group spanning \([\min(\texttt{in\_dttm}),\, \max(\texttt{out\_dttm})]\). Back-to-back ICU rows form a single ICU stay.
First / second ICU stay
Rank the merged ICU groups by in_dttm. Group 1 yields \(t^{\text{ICU}_1,\text{start}}_i, t^{\text{ICU}_1,\text{end}}_i\). Group 2, if present, is the unplanned readmission with start second_icu_start_time.
Prediction time
\(\text{prediction\_dttm}_i = t^{\text{ICU}_1,\text{end}}_i\) (decision made at first-ICU discharge).
Input window
\([\text{window\_start}_i,\, \text{window\_end}_i] = [t^{\text{ICU}_1,\text{start}}_i,\, t^{\text{ICU}_1,\text{end}}_i]\) — the entire first ICU stay (variable length; no fixed lookback).
Label (label_icu_readmission)
\[ y_i = \mathbb{1}\!\left[\texttt{second\_icu\_start\_time}_i \neq \varnothing\right]. \]

Cohort

  • Age at admission \(\ge 18\) with valid admission_dttm and discharge_dttm.
  • \(\ge 1\) ICU ADT record (first ICU stay defined).
  • Exclude hospitalizations with no ICU data — realized as an inner join with the timing table.
  • Exclude death during the first ICU stay (death_dttm ∈ \([t^{\text{ICU}_1,\text{start}}_i, t^{\text{ICU}_1,\text{end}}_i]\)): the readmission outcome is undefined.
  • Exclude direct ICU discharge (the last merged location is ICU): no opportunity to readmit.
  • Exclude a first ICU stay shorter than MIN_ICU_STAY_HOURS = 1 hour.
  • Exclude an intermediate ER visit (an ER location after the first location), which confounds the planned/unplanned distinction.

CLIF tables and categories used

Task T5 reads three CLIF v2.1 tables. The entire readmission signal is the adt.location_category sequence; hospitalization and patient provide cohort filters, the death timestamp, and demographics.

No labs, vitals, or medication tables are read — the task is ADT-only.

Columns selected:

  • hospitalization: hospitalization_id, patient_id, admission_dttm, discharge_dttm, age_at_admission, discharge_category.
  • patient: patient_id, sex_category, race_category, ethnicity_category, death_dttm.
  • adt: hospitalization_id, location_category, in_dttm, out_dttm.

Build pipeline for T5. Solid arrows: main flow. Dashed red arrows: exclusions. The diamonds gate hospitalizations on death-in-ICU, direct ICU discharge, short stay, and intermediate ER. The label is set by the existence of a second merged ICU stay after procedural-sandwich removal and consecutive-location merging.

  1. Load CLIF tables: hospitalization, patient, adt via base_icu_cohort.
  2. Apply adult-ICU cohort filters (age, valid admission/discharge, ≥1 ICU ADT).
  3. compute_readmission_timing(adt): map locations; drop ICU → Procedural → ICU rows; merge consecutive same-location rows; rank ICU groups to extract first/second ICU times; flag is_direct_icu_discharge and has_intermediate_er.
  4. Inner-join timing into the cohort (drops no-ICU hospitalizations).
  5. Apply the four remaining exclusions: death during first ICU stay; direct ICU discharge; first ICU stay < 1h; intermediate ER.
  6. Label \(y_i = \mathbb{1}[\texttt{second\_icu\_start\_time} \neq \varnothing]\).
  7. Set prediction_dttm = ICU₁ end and input window \([t^{\text{ICU}_1,\text{start}}, t^{\text{ICU}_1,\text{end}}]\).
  8. Assign temporal split (keyed on prediction_dttm); select OUTPUT_COLS; persist as parquet.

Design choices and rationale

Why ADT-only

ICU readmission is a movement event, fully observable from the CLIF ADT location stream without labs, vitals, or notes. Restricting the label to ADT keeps it portable across every CLIF site and avoids the cadence/vocabulary assumptions that complicate the lab- and medication-anchored tasks. The federated ML literature treats unplanned ICU readmission as a structured-EHR target in exactly this spirit [Rojas 2018].

Why remove the procedural sandwich

A patient who leaves the ICU for a scheduled procedure (OR, cath lab, interventional radiology) and returns has not been readmitted in any clinically meaningful sense — the return was planned at the time of transfer. Counting it would inflate the positive rate with non-events and penalize a model for “missing” an outcome that carries no deterioration signal. Collapsing ICU → Procedural → ICU to a single stay encodes the planned/unplanned distinction at the cohort level. Procedural rows that are not bracketed by ICU on both sides are left in place.

Why one-per-stay (not continuous)

Unlike the deterioration tasks, readmission has a single natural decision point — the moment of ICU discharge, when a clinician decides the patient is stable enough to leave. A one-per-stay framing matches that decision and keeps the label balanced (each hospitalization contributes one row rather than many trivially-negative hourly rows).

Why the four post-cohort exclusions

Death in the first ICU stay makes the outcome undefined; a direct ICU discharge removes any opportunity to readmit (a structurally guaranteed negative); a sub-hour first ICU stay is typically an administrative artifact rather than a true ICU course; an intermediate ER visit muddies the planned/unplanned reading of a subsequent ICU entry. Each is a deterministic ADT/timestamp predicate, applied in a fixed order.

Out of scope

  • Cross-hospitalization (30-day) ICU or hospital readmission.
  • Third and later ICU readmissions within a stay.
  • Time-to-readmission (survival) labels.
  • ICD- or problem-list–based planned/unplanned adjudication (ADT location categories only).
  • Input feature design.
