Unplanned ICU Readmission

At the end of a patient's first ICU stay, predict whether the patient will return to the ICU later in the same hospitalization through an unplanned path. The signal is derived entirely from the CLIF ADT location history. A return must contain an intervening Ward location to count as a readmission. An ICU return through Other without a Ward does not set the label and does not change the first ICU stay or prediction time. One prediction per surviving hospitalization.

Code note Implemented in icu_readmission.py on the stitched-encounter grain: compute_readmission_timing runs across the whole stitched encounter's ADT stream, so a true re-admission that the stitcher merged is read as one continuous location history. Constant verified against code: MIN_ICU_STAY_HOURS = 24.

FLAIR operational definition

Anchors and windows

Let \(H_i\) denote a hospitalization. From the CLIF ADT table, compute_readmission_timing computes a merged location sequence and, from it, the first ICU-stay window \([t^{\text{ICU}_1,\text{start}}_i,\, t^{\text{ICU}_1,\text{end}}_i]\) and the start time of a second ICU stay (if any).

Location standardization
Each adt.location_category is lowercased and mapped to a coarse bucket std_location ∈ {ICU, Ward, ER, Procedural, Radiology, Dialysis, Other} via LOCATION_MAPPING. Stepdown, L&D, hospice, psych, rehab, and other map to Other.
Consecutive-location merge
Consecutive rows with an equivalent std_location are merged into one group spanning \([\min(\texttt{in\_dttm}),\, \max(\texttt{out\_dttm})]\). Back-to-back ICU rows form a single ICU stay, and Procedural, Radiology, and Dialysis count as one equivalent location, so a mixed allowed-gap trip becomes one group.
Allowed-gap removal, then re-merge
Any allowed-gap group (Procedural / Radiology / Dialysis) whose immediate predecessor and successor (within \(H_i\), ordered by in_dttm) are both ICU is deleted, and the groups are merged again, so the two ICU groups either side collapse into a single ICU stay. Merging before the drop is what lets a multi-row allowed trip be recognised as one interval.
Ward-required return
After the first ICU group, the first later ICU group with at least one intervening Ward group supplies second_icu_start_time. Other-only returns are ignored for the label without changing the first ICU group's start or end.
First / second ICU stay
Rank the merged ICU groups by in_dttm. Group 1 yields \(t^{\text{ICU}_1,\text{start}}_i, t^{\text{ICU}_1,\text{end}}_i\). The unplanned readmission is the first later ICU group after an intervening Ward group (require_ward_return=True, see above); its start is second_icu_start_time.
Prediction time
\(\text{prediction\_dttm}_i = t^{\text{ICU}_1,\text{end}}_i\) (decision made at first-ICU discharge).
Feature cutoff
feature_cutoff_dttm = prediction_dttm: all data up to the first-ICU discharge may be used (no fixed lookback, no window columns).
Label (label_icu_readmission)
\[ y_i = \mathbb{1}\!\left[\texttt{second\_icu\_start\_time}_i \neq \varnothing\right]. \]

Cohort

  • Age at admission \(\ge 18\) with valid admission_dttm and discharge_dttm.
  • \(\ge 1\) ICU ADT record (first ICU stay defined).
  • Exclude hospitalizations with no ICU data — realized as an inner join with the timing table.
  • Exclude death during the first ICU stay (death_dttm ∈ \([t^{\text{ICU}_1,\text{start}}_i, t^{\text{ICU}_1,\text{end}}_i]\)): the readmission outcome is undefined.
  • Exclude direct ICU discharge (the last merged location is ICU): no opportunity to readmit.
  • Exclude a first ICU stay shorter than MIN_ICU_STAY_HOURS = 24 hours: too brief to have produced the ICU-discharge decision the prediction is anchored on.
  • Exclude an intermediate ER visit (an ER location after the first location), which confounds the planned/unplanned distinction.

CLIF tables and categories used

Task T5 reads three CLIF v2.1 tables. The entire readmission signal is the adt.location_category sequence; hospitalization and patient provide cohort filters, the death timestamp, and demographics.

CLIF tableCategory columnUse
hospitalization—cohort/demographics join; age_at_admission, valid dates
patient—demographics join; death_dttm for the death exclusion
adtlocation_categorynormalized into ICU / Ward / ER / Procedural / Radiology / Dialysis / Other; sole readmission signal

No labs, vitals, or medication tables are read — the task is ADT-only.

Columns selected:

  • hospitalization: hospitalization_id, patient_id, admission_dttm, discharge_dttm, age_at_admission, discharge_category.
  • patient: patient_id, sex_category, race_category, ethnicity_category, death_dttm.
  • adt: hospitalization_id, location_category, in_dttm, out_dttm.

The label is set by the existence of a later ICU stay with an intervening Ward after allowed-gap removal and equivalent-location merging.

  1. Load CLIF tables: hospitalization, patient, adt via base_icu_cohort.
  2. Apply adult-ICU cohort filters (age, valid admission/discharge, ≥1 ICU ADT).
  3. compute_readmission_timing(adt): map locations; merge equivalent-location runs; drop allowed procedural/radiology/dialysis gaps bracketed by ICU and re-merge; preserve the first ICU timing; select the first later ICU with an intervening Ward; flag is_direct_icu_discharge and has_intermediate_er.
  4. Inner-join timing into the cohort (drops no-ICU hospitalizations).
  5. Apply the four remaining exclusions: death during first ICU stay; direct ICU discharge; first ICU stay < MIN_ICU_STAY_HOURS (24h); intermediate ER.
  6. Label \(y_i = \mathbb{1}[\texttt{second\_icu\_start\_time} \neq \varnothing]\).
  7. Set prediction_dttm = feature_cutoff_dttm = ICU₁ end.
  8. Assign the train/test split (temporal; random 75/25 for site="mimic"; keyed on prediction_dttm); select OUTPUT_COLS; persist as parquet.

Design choices and rationale

Why ADT-only

ICU readmission is a movement event, fully observable from the CLIF ADT location stream without labs, vitals, or notes. Restricting the label to ADT keeps it portable across every CLIF site and avoids the cadence/vocabulary assumptions that complicate the lab- and medication-anchored tasks. The federated ML literature treats unplanned ICU readmission as a structured-EHR target in exactly this spirit [Rojas 2018].

Why require an intervening Ward location

A patient must first reach a Ward before a later ICU entry is considered a readmission. Returns through only Other can reflect internal transfers, recovery areas, or site-specific ADT mappings rather than a completed ICU discharge. These returns are ignored for the label while preserving the original first ICU stay and prediction time. Procedural, Radiology, and Dialysis gaps retain their standard merge behavior.

Why one-per-stay (not continuous)

Unlike the daily continuous tasks, readmission has a single natural decision point — the moment of ICU discharge, when a clinician decides the patient is stable enough to leave. A one-per-stay framing matches that decision and keeps the label balanced (each hospitalization contributes one row rather than many daily rows).

Why the four post-cohort exclusions

Death in the first ICU stay makes the outcome undefined; a direct ICU discharge removes any opportunity to readmit (a structurally guaranteed negative); a first ICU stay shorter than 24h is too brief to have produced the ICU-discharge decision the prediction is anchored on; an intermediate ER visit muddies the planned/unplanned reading of a subsequent ICU entry. Each is a deterministic ADT/timestamp predicate, applied in a fixed order.

Out of scope

  • Cross-hospitalization (30-day) ICU or hospital readmission.
  • Third and later ICU readmissions within a stay.
  • Time-to-readmission (survival) labels.
  • ICD- or problem-list–based planned/unplanned adjudication (ADT location categories only).
  • Input feature design.
