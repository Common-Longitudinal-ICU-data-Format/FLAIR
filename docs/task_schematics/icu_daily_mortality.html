ICU Daily In-Hospital Mortality at 07:00 Local

At every local 07:00 rounds anchor during the first ICU stay, predict whether the hospitalization will end with the patient dying in hospital, defined by CLIF discharge_category ∈ {Expired, Hospice}. The cohort is all adult ICU hospitalizations — unconditional: no discharge_category filter; every retained stay contributes daily rows, with null and Still Admitted dispositions kept as label-0. Task T2 shares the same cohort and grid with a different (non-complementary) label.

Code note Implemented in icu_daily_mortality.py on the stitched-encounter grain (hospitalization_join_id): read every \(H_i\) below as a stitched encounter, its members folded via the encounter index (default gap 6h). Label column label_mortality; display name “ICU Daily In-Hospital Mortality (7AM, binary)”.

FLAIR operational definition

Anchors and windows

Let \(H_i\) denote a hospitalization with admission time \(t^{\text{adm}}_i\) and discharge or death time \(t^{\text{end}}_i = \min(t^{\text{disch}}_i,\, t^{\text{death}}_i)\). Let \(t^{\text{ICU}_1,\text{start}}_i\) and \(t^{\text{ICU}_1,\text{end}}_i\) be the first ICU-stay endpoints returned by compute_icu_timing on the CLIF ADT table. All datetimes are naive but wall-clock-local per cfg["timezone"]; literal hours are local hospital time.

Prediction-window start (pred_start)
\[ \text{pred\_start}_i = \text{trunc}\!\bigl(t^{\text{ICU}_1,\text{start}}_i,\,1\text{d}\bigr) + 1\text{d} + 7\text{h}. \] The first decision point is local 07:00 on the calendar day after first ICU admission. A patient admitted at 03:00 Monday gets their first prediction at 07:00 Tuesday.
Prediction-window stop (pred_stop)
\[ \text{pred\_stop}_i = \min\!\bigl(t^{\text{ICU}_1,\text{end}}_i,\, \texttt{coalesce}(t^{\text{death}}_i,\, t^{\text{disch}}_i)\bigr). \] Predictions cease at the end of the first ICU stay or the end of the hospitalization (death if recorded, else discharge), whichever comes first.
Decision-point grid
Daily 24h step: \( D_i = \{\text{pred\_start}_i + k\cdot 24\text{h} : k\in\mathbb{Z}_{\ge 0},\ \text{pred\_start}_i + k\cdot 24\text{h} < \text{pred\_stop}_i\} \).
Label (label_mortality)
Let \(\texttt{disp}_i = \texttt{lower}(\texttt{strip}(\texttt{discharge\_category}_i))\). For \(d \in D_i\): \[ y_i(d) = \mathbb{1}\!\left[ \texttt{disp}_i \in \{\texttt{"expired"},\, \texttt{"hospice"}\} \right]. \] A null disp or any non-matching value (Home, SNF, Rehab, LTACH, AMA, Other, Still Admitted, …) yields \(y_i(d)=0\). The label is constant across all rows of \(H_i\) — the eventual disposition is a single fact broadcast to every grid point.

Cohort (unconditional)

  • Age at admission \(\ge 18\) with valid admission_dttm and discharge_dttm.
  • \(\ge 1\) ICU ADT record (first ICU stay is defined).
  • First ICU stay long enough to contain at least one 07:00 grid point after the admission day (i.e. \(\text{pred\_start}_i < \text{pred\_stop}_i\)).

There is no discharge_category filter. Stays discharged Home, SNF, Rehab, LTACH, AMA, Other, with Still Admitted status, or with null discharge_category all remain in the cohort and carry label-0.

CLIF tables and categories used

Task T1 reads three CLIF v2.1 tables.

CLIF tableCategory columnUsage
hospitalizationdischarge_category Label-only: \(y=1\) iff lower/strip value ∈ {Expired, Hospice}; null / Still Admitted / any other ⇒ \(y=0\). No cohort filter on this column.
adtlocation_category Cohort filter: \(\ge 1\) row with value "icu" (case-insensitive).
patient— Join only; no category filter. Provides death_dttm for pred_stop.

Canonical discharge_category values mapping to label-1 (case-insensitive after lower+strip): Expired, Hospice. Every other canonical value (Home, SNF, Acute Inpatient Rehab Facility, LTACH, Acute Care Hospital, Group Home, Chemical Dependency, AMA, Assisted Living, Still Admitted, Missing, Other, Psychiatric Hospital, Shelter, Jail) plus null maps to label-0.

Columns selected:

  • hospitalization: hospitalization_id, patient_id, admission_dttm, discharge_dttm, age_at_admission, discharge_category.
  • patient: patient_id, sex_category, race_category, ethnicity_category, death_dttm.
  • adt: hospitalization_id, location_category, in_dttm, out_dttm.

Build pipeline shared by Tasks T1 and T2. The two tasks consume the same cohort, grid, and 24h lookback; they differ only in the final label predicate.

  1. Load CLIF tables: hospitalization, patient, adt.
  2. Build the adult cohort with valid admission/discharge times.
  3. Restrict to hospitalizations with \(\ge 1\) ICU ADT row.
  4. Compute first-ICU-stay window via compute_icu_timing(adt).
  5. Compute pred_start by truncating \(t^{\text{ICU}_1,\text{start}}_i\) to date, adding 1 day, then 7 hours.
  6. Compute pred_stop \(= \min(t^{\text{ICU}_1,\text{end}}_i,\, \texttt{coalesce}(t^{\text{death}}_i, t^{\text{disch}}_i))\).
  7. Explode the daily 07:00 grid \([\text{pred\_start}_i, \text{pred\_stop}_i)\) per encounter (pl.datetime_ranges, interval="24h", closed="left").
  8. Broadcast the label (disp ∈ {expired, hospice}, null-safe via fill_null(False)) to every grid row.
  9. Assign window_start = d − 24h, window_end = d (fixed 24h lookback).
  10. Apply temporal train/test split (flair_benchmark._split.assign_split), keyed on prediction_dttm.
  11. Select OUTPUT_COLS and persist as parquet.

Design choices and rationale

Why an unconditional cohort

Earlier drafts used a conditional-on-non-survival cohort (discharge_category ∈ {LTACH, Expired, Hospice}) to manufacture a balanced binary task. That was dropped: it conflated the cohort filter with the label predicate, made the per-row positive rate uninterpretable as “ICU mortality risk,” and produced a paired-task framing (T1 + T2 = 1) that misrepresented the clinical question. The unconditional design is the standard form of ICU in-hospital mortality prediction [MIMIC] and makes the per-row positive rate a meaningful ICU mortality prevalence (expected ~10–15% per-row positive in MIMIC-CLIF). AUPRC is reported alongside AUROC.

Why 07:00 local rounds anchor

ICU morning rounds are the canonical decision cadence; predictions produced before rounds are actionable that day, after rounds are not. The 07:00 timestamp is a wall-clock-local literal, relying on flair_benchmark._clif.pd_to_pl having stripped timezone info from clifpy datetimes (typed to cfg["timezone"]). Sites preferring 06:00 or 08:00 re-anchor by adjusting PRED_HOUR without changing the rest of the pipeline.

Why daily (not hourly)

The decision being modeled — terminal-trajectory commitment — does not change hour-to-hour. A daily cadence matches the clinical question and keeps row counts manageable.

Why Hospice counts as mortality

CLIF separates Expired (death in hospital) from Hospice (alive at discharge to hospice). T1 bundles them: transition-to-hospice is the operational equivalent of a death-in-hospital trajectory — goals of care have shifted from cure to comfort, and the morning-rounds prediction horizon is identical. Sites wanting the strict CLIF definition (Expired only) adjust the literal-set in icu_daily_mortality.py.

Why null / Still Admitted are kept as label-0

Dropping these would silently shrink the denominator and bias prevalence upward. Treating them as negatives matches the standard in-hospital mortality definition: “did this patient die during this encounter? If we don't see a death-coded disposition, assume no.” Sites with persistent Still Admitted contamination should investigate that data-quality gap separately.

Out of scope

  • Multi-class extension to alive-other dispositions (Home, SNF, Rehab, AMA) or LTACH as a third class.
  • Hospital-wide (non-ICU) variant.
  • Input feature engineering and severity-score baselines (e.g. APACHE-III [APACHE III], SAPS-II).
  • Survival-time / time-to-event variant.
