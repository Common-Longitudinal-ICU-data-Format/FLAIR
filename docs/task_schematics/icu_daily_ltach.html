ICU Daily LTACH Discharge at 07:00 Local

At every local 07:00 rounds anchor during the first ICU stay, predict whether the hospitalization will end with transfer to a Long-Term Acute Care Hospital (CLIF discharge_category = Long Term Care Hospital (LTACH)). The cohort is identical to Task T1 (all adult ICU hospitalizations, no discharge_category filter); only the label predicate differs.

Code note Implemented in icu_daily_ltach.py on the stitched-encounter grain. Label column label_ltach; display name “ICU Daily LTACH Discharge (7AM, binary).” Build pipeline is shared with T1 (same module helpers).

Relationship to Task T1

The build pipeline of T2 is byte-identical to T1's: same cohort filters (adult, valid admission/discharge, \(\ge 1\) ICU ADT record, first ICU stay long enough for at least one 07:00 grid point), same pred_start, pred_stop, decision-point grid, and train/test split (temporal; random 75/25 for site="mimic"). There is no fixed lookback window: all history up to prediction_dttm is usable. Neither task filters on discharge_category at the cohort stage. The only difference is the final label rule. See the full operational definition in Task T1; the flowchart below is shared.

Label rule (Task T2 only)

Let \(\texttt{disp}_i = \texttt{lower}(\texttt{strip}(\texttt{discharge\_category}_i))\). For \(d\) in the daily 07:00 decision grid \(D_i\):

\[ y_i(d) = \mathbb{1}\!\left[\,\texttt{disp}_i\ \text{matches regex}\ \texttt{ltach|long.?term}\,\right]. \]
  • The label is constant across all rows of \(H_i\) (the eventual disposition is a single encounter-level fact broadcast to every grid point).
  • A null disp or any non-matching value (Expired, Hospice, Home, SNF, Acute Inpatient Rehab Facility, AMA, Other, Still Admitted, …) yields \(y_i(d)=0\).
  • Non-partition property: because T1 and T2 share the same unconditional cohort with non-overlapping predicates, \(\texttt{label\_mortality}_i + \texttt{label\_ltach}_i \le 1\) but not necessarily \(= 1\). A Home discharge is 0 in both; an Expired discharge is 1 in T1 / 0 in T2; an LTACH discharge is 0 in T1 / 1 in T2.

CLIF tables and categories used

Identical to T1: three tables (hospitalization, patient, adt) and the same cohort filters. The ADT filter restricts to location_category = "icu" (case-insensitive); patient is join-only; discharge_category is read from hospitalization for the label only — no cohort filter on it. See the full table + column inventory in Task T1.

Design choices and rationale

Why a separate schematic for a different label on the same cohort

A reader scanning the supplement should find one document per FLAIR task, with its own META, label rule, and prevalence numbers. The shared build pipeline is a convenience of implementation, not a property of the task definition: a future revision of T2's regex (e.g. if the discharge_category taxonomy splits LTACH from other long-term destinations more finely) would not affect T1. The regex is fixed in icu_daily_ltach.py; changing it changes the task definition and its audit hash.

Prevalence and class imbalance

LTACH transfer is a rare disposition: across all adult ICU stays it sits in the low single digits per-row positive rate. Class imbalance is the dominant modelling challenge, so AUPRC is the primary headline metric. AUROC is reported but is optimistic on heavily imbalanced binary tasks.

Why LTACH is the operationally interesting label

LTACH transfer is a planned, resource-intensive disposition decision [Kahn 2010]. The task's clinical action (META["clinical_action"]) is to perform early tracheostomy: a morning prediction of an LTACH-bound trajectory flags patients for whom an early tracheostomy decision is on the table.

Why an unconditional cohort

Earlier drafts conditioned the cohort on the union of LTACH and in-hospital mortality, manufacturing a balanced binary against T1. That design was retired (see T1 design choices). The unconditional cohort makes the per-row positive rate interpretable as the prevalence of LTACH-bound trajectories among all ICU survivors-and-non-survivors.

Out of scope

  • All items in Task T1's out-of-scope list carry over.
  • Finer-grained LTACH-vs-skilled-long-term-care distinctions within the LTACH-positive class.
